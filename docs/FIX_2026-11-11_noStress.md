# 改修手順書：操作のイラッと3つを直す（2026-11-11）

咲耶フットボールを「ノーストレス」にする第1弾。なおなおが遊んで感じたイラッとポイント3つを直す。
対象ファイルは `index.html` だけ。シミュレーター要素（戦術・オンライン）はまだ足さない。

作業のルール
- 3つは**別々のコミット**にする（どれかが合わなければ、それだけ戻せるように）
- `stepMatch(cmd)` の形（入力はコマンドにして渡す）は崩さない。オンライン対戦の準備なので
- 数値はファイル上のほうの定数にまとめ、日本語のコメントを付ける（今のコードと同じ書き方）
- 操作説明（`help.mobile` / `help.pc`）と README の遊び方も、変えた操作に合わせて直す

## ① パス先を前もって光らせる

### いまの問題
パスの相手は、B を離した瞬間に `facingMate(p)` が「向いている方向の左右60度の中で、`off*1.5 + d*0.2` が一番小さい味方」を選ぶ。どの味方が選ばれるのかが蹴るまで見えないので、「思ってない味方に行った」と感じる。

### 直し方
1. ボールを持っている間（`M.ball.owner === M.controlled`）は、毎フレーム `facingMate(M.controlled)` を呼んで、結果を `M.passPreview` に入れる
   - `stepHuman` の最後あたりで計算する。持っていないときは `null`
2. `render` で、`M.passPreview` の選手の足もとに印を描く
   - 操作中の選手の目印（マゼンタ）とは別の色・形にする。例：水色（`#3bd1ff`）の点線の輪、または足もとの小さな▼
   - B を長押しして浮き玉になる長さ（`LOB_HOLD`）を越えたら、印の色を変える（浮き玉の落ちる場所の × と同じ水色系でよい）
3. パス先がいないとき（`facingMate` が `null`）は、向いている方向に短い矢印を出す（「この方向に蹴り出すよ」の合図）
4. 実際に蹴るときは、**表示していた相手にそのまま蹴る**こと（表示と実際がずれないように、`humanPass` は `M.passPreview` を優先して使う）

### 確かめること
- ボールを持って向きを変えると、印が味方の間を移っていく
- 印の出ている味方に、必ずパスが届く
- 印がちらつきすぎない（向きの細かいぶれで、2人の間を行ったり来たりしない）
  - ちらつくようなら、今の相手のコストを少し下げる（例：0.8倍）「くっつき」を入れる

## ② 走っている最中は勝手に切り替えない＋切り替わった瞬間を目立たせる

### いまの問題
`stepHuman` の最後で、ボールを持っていないときは「ボールに一番近い選手」へ自動で切り替わる（`dist(m, b) + 40 < dist(c, b)`）。スティックを倒して走っている最中でも切り替わるので、「さっきの選手を動かしていたつもりが別の選手になっている」が起きる。

### 直し方
1. 自動の切り替えは、**スティックを倒していないとき**（`Math.hypot(cmd.ax, cmd.ay) <= 0.08`）だけにする
   - スティックを離してから少し（例：8フレーム）たってから切り替える。離した直後に切り替わると、それはそれで驚くので
2. 次の切り替えは今までどおり残す
   - B ボタン（ボールを持っていないとき）
   - パスを出したとき（受け手に切り替わる。`passTo` の中）
   - ボールを奪ったとき・拾ったとき（`giveBall` の中）
3. **切り替わった瞬間を目立たせる**
   - どの理由で切り替わっても、`M.controlled` が変わったら `M.switchFlash = 20` のようにして、新しい選手の足もとを数フレーム、大きめの輪でピカッと光らせる（だんだん小さく・薄く）
   - 効果音 `SFX.switch()` を、B ボタン以外の切り替え（自動・パス・奪取）でも鳴らす。ただしパスの瞬間はパスの音とかぶるので、パスのときは鳴らさなくてよい
   - `M.controlled` を書き換えている場所が何か所もあるので、`setControlled(p)` のような関数を1つ作って、そこを通すようにすると楽

### 確かめること
- スティックを倒して走っている間は、ボールに別の味方が近づいても操作が変わらない
- スティックを離すと、少しして近い選手に切り替わり、足もとが光る
- B で切り替えたとき・パスを出したときも、新しい選手がすぐ分かる

## ③ ダッシュは押しっぱなしで

### いまの問題
画面の右側を1回たたくごとに `boost` が `DASH.tap`（0.3）増え、毎フレーム `DASH.decay` ずつ減る。速く走り続けるには連打し続けるしかなく、指が疲れる。

### 直し方
1. 入力を「たたいた回数」から「押している間」に変える
   - スマホ：画面の右側（ボタンの上は除く。今の `pointerdown` の判定と同じ範囲）を**押している間**ダッシュ。`pointerdown` で押した指の `pointerId` を覚え、同じ指の `pointerup` / `pointercancel` で離したことにする
   - PC：C キーを**押している間**ダッシュ（`keydown` / `keyup`。自動リピートは無視）
   - コマンドは `dashTaps` の代わりに `dashHeld: true/false` を渡す
2. `stepHuman` の `boost` の計算を変える
   - 押している間（かつバテていない）：`boost` を 1 に向けて素早く上げる（例：毎フレーム +0.12。いきなり最高速にしない）
   - 離したら：`boost` を 0 に向けて下げる（例：毎フレーム -0.08）
   - スタミナが減る・バテる・回復する仕組み（`DASH.drain` / `recover` / `recoverTo`）はそのまま使う。バテたら押していても走れない
3. ポーズ・設定画面・試合の切り替わりで、押しっぱなしの状態が残らないようにする（`onInputReset` で `dashHeld` を false に戻す）
4. 使わなくなった `DASH.tap` / `decay` と `dashTaps` は消す

### 確かめること
- 右側を押しっぱなしにすると速く走り、スタミナのゲージが減っていく
- スタミナが無くなると汗が出て、押していても普通の速さになる
- 指を離すとすぐ普通の速さに戻り、スタミナが回復していく
- A・B ボタンを押しながら、右側の空いたところを別の指で押しても、どちらもちゃんと効く
- ポーズして戻ったとき、ダッシュしっぱなしになっていない
