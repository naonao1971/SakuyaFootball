# 改修手順書：点が入る気持ちよさを足す（2026-11-12）

咲耶フットボールの第2弾。ノーストレスの3つ（11/11）は直したが、遊んでみて「いまいち」だった。
1983年のアーケードの見下ろし型サッカーのプレイ動画と見比べ、ちーちゃんが「気持ちいい瞬間が少ない」のが原因と見立てた。
対象ファイルは `index.html` だけ。シミュレーター要素（戦術・オンライン）はまだ足さない。

### 動画でわかったこと（見比べの元）
- 点がどんどん入る。キックオフから約17秒で1点目。1試合（2分）で 3-0、次の試合も開始28秒で1点
- 画面のほとんどが相手ゴール前。攻めている時間が長い
- ゴール前に来ると、ゴールの上に**ねらいの矢印**が出て左右に動く。矢印のところへ蹴る
- ゴールの瞬間：大きな文字、ゴール裏の応援団がいっせいに手を上げる、スコアが一気に増える
- ドリブル・パス・シュートのたびに、スコアが少しずつ増えていく（160→340→460→750）

### 今の咲耶フットボール
- 単純な自動操作で6試合：CNP 9 - 4 NINJA（1試合で CNP 1.5点くらい）。点が入る瞬間が少ない
- シュートは「左右を入れながら放すとすみを狙う」だが、どこへ飛ぶかは蹴るまで見えない
- ゴールは `GOAL!!` の文字・咲耶の「ゴール！」・観客が 2px 跳ねるだけ
- `kit.score.add` で点は入っている（奪って50、ゴール1000など）が、画面には出ない

作業のルール（11/11 と同じ）
- 4つは**別々のコミット**にする（どれかが合わなければ、それだけ戻せるように）
- `stepMatch(cmd)` の形（入力はコマンドにして渡す）は崩さない。オンライン対戦の準備なので
- 数値はファイル上のほうの定数にまとめ、日本語のコメントを付ける（今のコードと同じ書き方）
- 操作説明（`help.mobile` / `help.pc`）・README・`docs/PLAN.md` も、変えたところに合わせて直す

## ① 点を入りやすくする（いちばん大事）

### めあて
CNP チームが **1試合で平均3点くらい**、忍者チームは **1点くらい**。「攻めて、決まる」を2分で何回も味わえるようにする。

### 直し方
1. キーパーとシュートの数字を、上のほうの定数1か所にまとめる（今は `contacts()` と `stepKeeper()` の中に直書き）
   ```js
   // キーパーのキャッチの確率（ボールの速さ別）と、シュートに反応して横へ動く速さ
   const KEEPER = { catchSlow: 0.97, catchMid: 0.78, catchFast: 0.5, midSpeed: 6, fastSpeed: 9.5, dive: 1.7 };
   ```
   `KEEPER_DIVE_SPEED` はここへ移す
2. 次の順で少しずつゆるめ、そのたびに自動テスト（下）で点の数を見る。めあてに届いたらそこで止める
   - a. 強いシュートを取りにくくする：`catchMid` 0.78 → 0.65、`catchFast` 0.5 → 0.35
   - b. キーパーの横の動きを遅く：`dive` 1.7 → 1.45
   - c. 溜めたシュートを少し速く：`shoot()` の `7.5 + t * 5` → `7.5 + t * 6`
   - d. まだ足りなければ、忍者チームの奪う力を弱く：`ENEMY.steal` 0.035 → 0.025
3. 忍者チームの点が増えすぎたら、キーパーの数字はチームごとに分ける（CNP のキーパーは今のまま強く）

### 確かめること
- `window.__sim` で、単純な自動操作のまま10試合くらい早送りし、1試合あたりの点を出す（11/10 に AI を賢くしたときと同じやり方）。数字はコミットのメッセージと `docs/PLAN.md` に書く
- なおなおがスマホで1試合遊んで、「決まった！」が2〜3回あるか
- 簡単すぎないか（ノーシュートで点が入りまくらない。キーパーが正面のシュートはちゃんと取る）

## ② シュートのねらいを矢印で見せる

### めあて
ゴール前でボールを持ったら、「今蹴るとここへ飛ぶ」がゴールの上に見える。パス先を光らせた（11/11 ①）のと同じ考え方。

### 直し方
1. 操作中の選手がボールを持ち、相手ゴールの方を向いていて（`shoot()` の `p.fx * dir > 0.2` と同じ条件）、ゴールまで近い（例：`SHOT_AIM_RANGE = 420` 以内）ときだけ、`M.shotAim` に「ねらいの横位置」を入れる
   - 横位置は `shoot()` と**同じ式**で出す：`MIDY + aimY * GOAL_HALF * 0.85`（`aimY` はスティックの横の入力）
   - 式は関数にして、`shoot()` と矢印の両方から呼ぶ（表示と実際がずれないように）
2. `render` で、相手ゴールのラインの少し手前に、下向きの矢印（▼）を描く
   - 色は金（`c.gold`）。A を押して溜めている間は、溜めの強さに合わせて矢印を大きく・明るくする
   - パス先の印（水色）・操作中の目印（マゼンタ）と色がかぶらないように
3. 遠すぎる（範囲の外）・ゴールに背を向けている・浮き球待ちのときは出さない

### 確かめること
- ゴール前でスティックを左右に入れると、矢印がゴールの左右へ動く
- 矢印のところへ、ちゃんと飛んでいく（キーパーにはじかれるのは別）
- 矢印がちらつかない。ちらつくようなら、横位置を前のフレームとなめらかにつなぐ（例：`M.shotAim += (目標 - M.shotAim) * 0.3`）

## ③ ゴールの演出を派手にする

### めあて
決めた瞬間に「やった！」となる。今の `freeze(160, "goal")` の160フレームの中で、次をいっぺんに起こす。

### 直し方
1. **観客**：`drawStands` の `cheer` のとき、跳ねる高さを 2px → 5px にし、点を決めた側（CNP が決めたら画面の上のスタンド）だけ全員がいっせいに跳ぶ。ときどき紙吹雪（小さな色の四角が上から落ちる、30個くらい）
2. **画面**：決まった瞬間に白いフラッシュ（今の `M.flash = 20` を少し強く）と、画面を数フレーム揺らす（例：最初の12フレーム、振れ幅4px → 0）
3. **点数**：ゴールに入った場所の上に `+1000` を大きく出して、上へふわっと消す（④の仕組みを使う。④より先にやるなら、③の中で作って④で使い回す）
4. **CNP の選手**：決めた選手のまわりに、味方が寄ってくる（`freeze` の間、CNP のフィールドプレーヤーを決めた選手へゆっくり `seek` させる）
5. 忍者チームが決めたときは、控えめ（観客は下のスタンドだけ・紙吹雪なし・揺れなし）

### 確かめること
- CNP が決めたときに、観客・フラッシュ・揺れ・点数・選手の集まりが全部出る
- 忍者チームが決めたときは控えめ
- 揺れで文字が読みにくくならない。気分が悪くなるほど揺れない（設定の「画面効果を減らす」があれば、そのときは揺らさない）

## ④ 細かいプレーにも点数を見せる

### めあて
奪った・つないだ・シュートを打った、のたびに「+50」がポンと出て、うまくいったのが分かる。

### 直し方
1. 点数の表示を1つの関数にまとめる：`addPoints(n, x, y)`
   - 中で `kit.score.add(n)` を呼び、`M.popups` に `{ text: "+" + n, x, y, t: 40 }` を足す（x, y はワールド座標）
   - `render` で、`M.popups` を上へ少しずつ動かしながら描き、`t` が減ったら薄くして消す。文字は `k.retro.font`、色は金
   - 今 `kit.score.add` を呼んでいるところ（奪う50・スライディング50・ゴール1000・CNP の記録300）は、全部 `addPoints` に変える（試合終わりの勝ちのボーナスは、文字の大きな表示があるので今のままでよい）
2. 新しく点を付けるところ（CNP チームだけ）
   - パスが味方に届いた：+30（受け手の足もと）
   - 枠に飛んだシュート：+100（キーパーに取られても付ける。打ったことをほめる）
   - ドリブルで相手を1人抜いた：+50（できればでよい。難しければ後回し）
3. 点が増えたので、`maxScore` のコメント（試作の仮）と `_games` の上限も合わせて見直す

### 確かめること
- 奪う・つなぐ・打つ、のたびに数字が出て、左の余白のスコアもその分増える
- 数字がたくさん出ても、ボールや選手が見えなくならない（同時に出るのは多くて3〜4個）
